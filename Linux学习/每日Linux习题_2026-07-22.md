**第1题**（命令实战 · grep）

你想在 `server.log` 中找出所有包含 "ERROR" 或 "FATAL" 的行，同时显示匹配行的行号。以下哪个命令是正确的？

A. `grep "ERROR|FATAL" server.log`
B. `grep -n -E "ERROR|FATAL" server.log`
C. `grep -n "ERROR" -o "FATAL" server.log`
D. `grep --count "ERROR|FATAL" server.log`

---

**第2题**（命令实战 · find）

你需要在 `/var/log` 目录及其子目录下，查找所有 **7天前修改过** 且 **扩展名为 .log** 的文件，并列出详细信息（类似 `ls -l` 的效果）。正确的命令是？

A. `find /var/log -name "*.log" -mtime +7 -ls`
B. `find /var/log -type f -name "*.log" -mtime -7 -ls`
C. `find /var/log -name "*.log" -atime +7 -exec ls -l {} \;`
D. `find /var/log -type f -name "*.log" -mtime +7 -exec ls -l {} \;`

**第3题**（综合应用 🔥）

生产环境的 Java 应用突然 CPU 飙到 100%。你需要快速找到：**哪个 Java 进程占用 CPU 最高**，然后**看看这个进程打开了哪些文件**（以便排查是否某个日志文件疯狂写入）。

请写出你需要用到的两个命令（假设你知道进程名里含 "java"）：

```
# 第一步：找到最高 CPU 的进程信息（写出命令）
?

# 第二步：查看该进程打开的所有文件（写出命令，假设 PID=12345）
?
```

🔑 **答案揭晓**

---

**第1题答案：B**

| 选项 | 分析 |
|------|------|
| A | ❌ 管道符 `|` 在基础正则中只是普通字符，需要用 `-E`（扩展正则）或 `\|` 转义才能表示"或" |
| B | ✅ `-n` 显示行号，`-E` 启用扩展正则，`ERROR|FATAL` 正确匹配两个关键词 |
| C | ❌ `-o` 是"只输出匹配部分"，不能接第二个模式 |
| D | ❌ `--count` 只输出匹配行数，不显示内容；且同样没处理 `|` 的转义问题 |

💡 实用技巧：grep 的 `-E` 是最常用的正则开关，日常写 `grep -nE "keyword1|keyword2" file` 就能搞定大部分查找需求。

---

**第2题答案：D**

| 选项 | 分析 |
|------|------|
| A | ❌ `-ls` 是 GNU find 的扩展选项，但不是所有系统都支持（BSD 就没有） |
| B | ❌ `-mtime -7` 表示"7天内修改过的"，正好和题意**反了**！`+7` 才是"超过7天" |
| C | ❌ `-atime` 是**访问时间**而不是修改时间；且少了 `-type f` |
| D | ✅ `-type f` 限定文件，`-mtime +7` 表示7天前修改，`exec ls -l {} \;` 对每个结果执行 `ls -l` 显示详情 |

💡 **mtime 记忆口诀**：`-mtime +N`（大于N天） = "老了"；`-mtime -N`（小于N天） = "年轻"。可以记成"老+少-"。

**第3题答案：**

```bash
# 第一步：找 CPU 最高的 java 进程
ps aux --sort=-%cpu | grep java | head -5

# 或更简洁
ps aux | grep java | sort -k3 -rn | head -5
```

```bash
# 第二步：查看 PID=12345 的进程打开了哪些文件
lsof -p 12345

# 只看日志文件的话加个 grep
lsof -p 12345 | grep "\.log"
```

💡 **排障思路**：
- `ps aux --sort=-%cpu` 按 CPU 降序排列，`head` 截取前几条，一眼看到罪魁祸首
- `lsof -p PID` 是该进程的"档案袋"，能看到它打开了什么文件、网络连接、管道等
- 实际工作中，CPU 飙高常见原因：死循环、GC 频繁、日志疯狂刷盘 → lsof 能帮你确认是不是最后一种
