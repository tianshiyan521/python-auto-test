# 游戏测试面试题集（2026 最新版）

> 涵盖基础概念、BUG管理、专项测试、工具能力、逻辑题 5 大类，共 30 题，附参考答案。

---

## 一、基础概念类

### 1. 什么是游戏测试？主要目标是什么？
**答：** 游戏测试是对游戏产品进行全面检测的过程。主要目标是**发现并报告 BUG 和不足**，确保游戏质量和玩家体验。

### 2. 游戏测试的类型有哪些？
**答：** 功能测试、兼容性测试、性能测试、冒烟测试、回归测试、稳定性测试、用户体验测试。

### 3. 黑盒测试 vs 白盒测试
**答：** 黑盒不关注内部代码，只看功能和表现；白盒关注代码实现和流程。**游戏测试以黑盒为主。**

### 4. 游戏测试 vs 软件测试的异同
**答：**
- **相同：** 测试流程、BUG 管理、用例设计思路
- **不同：** 游戏更重**体验、交互、性能、兼容性**，主观评价占比大

### 5. 什么是冒烟测试？
**答：** 对新版本进行**基础功能快速验证**，核心功能可用才进入深入测试。类似于"先闻一下有没有烧焦"。

### 6. 什么是 Monkey 测试？适合游戏吗？
**答：** 随机生成大量操作输入，适合发现崩溃类问题，但对游戏逻辑性 BUG 帮助有限。

## 二、BUG 管理类

### 7. BUG 严重等级怎么划分？

| 等级 | 说明 | 示例 |
|------|------|------|
| 致命（Blocker） | 游戏崩溃/无法运行 | 登录即闪退 |
| 严重（Major） | 核心功能不可用 | 商城打不开 |
| 一般（Normal） | 功能异常但不影响整体 | UI 错位 |
| 轻微（Minor） | 不影响功能的瑕疵 | 文字错误 |
| 建议（Suggestion） | 体验优化建议 | 按钮太小 |

### 8. BUG 报告模板（标准写法）
```
标题：简要描述问题
版本：发现时的版本号
设备：手机型号/PC配置/系统版本
步骤：1.打开游戏 → 2.点击XX → 3.……
实际结果：发生了什么
预期结果：应该发生什么
截图/录像：附件
严重等级：致命/严重/一般/轻微
```

### 9. 偶现 BUG 怎么处理？
**答：** 详细记录环境、操作步骤、日志；尝试多种条件复现（切换设备、切换网络）；必要时协助开发加日志定位。

### 10. 什么是回归测试？为什么重要？
**答：** 修复 BUG 或新增功能后，对**相关区域再次测试**，防止旧问题复发或引入新问题。

## 三、专项测试类

### 11. 如何测试多人在线游戏的网络稳定性？
**答：** 模拟不同网络环境（延迟 100ms/500ms、丢包 10%/30%、断线重连），多人同时操作，观察同步和异常表现。

### 12. 如何测试内购/支付系统？

**答：**
- 模拟真实支付流程：发起 → 确认 → 成功/失败/取消
- 覆盖所有支付方式（微信/支付宝/苹果等）
- 验证：扣款正确、道具到账、异常退款处理
- 断网环境下支付的行为

### 13. 如何测试存档/读档功能？

**答：**
- 在不同进度、状态下存档（战斗中 / 副本中 / 挂机中）
- 重启游戏读档，验证数据一致、无丢失
- 跨版本升级后存档兼容性

### 14. 如何测试游戏兼容性？
**答：** 在多机型、系统版本、分辨率下跑游戏，关注画面、操作、性能是否一致。重点关注低端机和主流机型。

### 15. 如何测试 UI 界面？
**答：** 布局适配、按钮可点击/不可点击状态、文字无错别字、界面切换流畅、各种分辨率下不穿帮。

### 16. 什么是压力测试？怎么做？
**答：** 模拟**大量用户同时在线**，观察服务器和客户端承载极限。常用机器人/自动化脚本模拟并发操作。

## 四、工具与能力类

### 17. 你熟悉的自动化测试工具有哪些？
**答：** Selenium（Web）、Airtest（手游/PC游戏）、Appium（移动端）、pywinauto（Windows桌面）、Poco（游戏UI识别）。

### 18. 自动化测试在游戏测试中怎么用？
**答：** 适合**重复性高、流程固定**的测试（跑图、日常任务、回归测试），不适合体验评价和主观判断。

### 19. 如何与开发/美术协作？
**答：** BUG 附上复现步骤 + 截图/日志，不写"有 bug"三个字就扔过去。尊重各岗位职责，有事说事。

### 20. 优秀游戏测试人员需要什么素质？
**答：** 细心、耐心、逻辑思维、沟通能力、热爱游戏、学习能力强。最重要的是：**能站在玩家角度看问题。**

## 五、逻辑与场景题

### 21. 游戏里 NPC 对话出现错别字，你怎么处理？
**答：** 截图 + 标注正确写法 + 记录具体 NPC 名和任务名 → 提到 TAPD 上，标记为轻微/一般。

### 22. 玩家反馈"游戏很卡"，你怎么排查？
**答：**
1. 确认设备配置和使用场景
2. 复现：同场景同操作测试帧率
3. 检查资源加载、内存占用
4. 对比不同画质设置下的表现
5. 配合开发看 Profiler 数据

### 23. 某个怪物掉落率 5%，怎么验证？
**答：** 杀 1000 次统计掉落次数，看是否在置信区间内（期望 50 次 ± 合理偏差）。小样本不靠谱，必须大量测试。

### 24. 上线前一天发现一个偶现闪退 BUG，怎么办？
**答：** 立刻上报 + 标注严重等级 + 提供日志和复现步骤 + 建议是否延期上线。由项目经理和技术负责人决策。

### 25. 你如何设计一个新功能的测试用例？
**答：**
1. 读需求文档，理解功能逻辑
2. 用**边界值 + 等价类 + 场景法**设计用例
3. 覆盖：正常流程 + 异常流程 + 边界条件 + 兼容性
4. 标注优先级（P0/P1/P2）

## 六、加分项：游戏理解

### 26. 你最近玩过哪些游戏？能说说它的优缺点吗？
> **建议提前准备**：挑 2-3 款熟悉的手游/端游，从玩法、UI、付费、BUG 角度聊。

### 27. 你对"恐龙岛"这类游戏的理解？
> **结合你的实际项目经验**：领地争夺玩法、恐龙存储机制、自动挂机系统、大乱斗模式——这些你天天测，面试时最有说服力。
