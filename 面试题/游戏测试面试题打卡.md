## Day 1 - 2026-06-08

### 题目
在线游戏中，TCP 和 UDP 两种网络协议有什么区别？以恐龙岛这类 MMO 游戏为例，哪些场景用 TCP、哪些用 UDP？如果让你测试领地争夺玩法的网络同步，你会关注什么？

### 答案
- **TCP**：面向连接，可靠送达，保证顺序，速度慢。用于登录、支付、聊天、背包等数据不能丢的场景。
- **UDP**：无连接，不保证送达和顺序，速度快。用于位置同步、实时战斗等延迟敏感场景。
- **恐龙岛对应**：TCP → 登录/商城/道具；UDP → 角色移动/战斗同步；混合 → 战斗用UDP、结算用TCP。
- **领地争夺网络测试**：关注不同延迟下同步一致性、断线重连后状态恢复、丢包时技能同步表现。

### 方向
网络协议类

## Day 2 - 2026-06-09

### 题目
恐龙岛上线后，大量玩家反馈"打领地争夺战时画面特别卡"。作为测试人员，你如何系统性地排查和定位这个问题？请描述你的测试思路和具体关注点。

### 答案
1. **确认信息**：收集玩家设备型号、系统版本、画质设置、战斗参与人数等基础信息，判断是普遍问题还是特定机型问题。
2. **区分卡的类型**：先确认玩家说的"卡"是**帧率低**（画面不流畅）还是**延迟高**（操作后半天才有反应）——两者排查方向完全不同。
3. **本地复现**：用相同或更低配设备，在领地争夺场景复现。用 PerfDog/GPU Profiler 监测帧率、CPU、内存、GPU 占用，拿到具体数据。
4. **分步定位**：
   - 人数变量：10人 vs 30人 vs 50人同屏帧率对比
   - 特效变量：关闭技能特效/粒子效果后帧率是否回升
   - 资源变量：连续打多场后内存是否持续上涨（内存泄漏）
   - 画质变量：不同画质档位下帧率差异
5. **网络排除**：确认不是网络问题——网络延迟高是"瞬移/回弹"，帧率低是"画面不连贯"，能区分才能精准定位。
6. **输出报告**：具体数据（最低帧率、平均帧率、卡顿频率）+ 优化建议（减少同屏特效、LOD优化、对象池复用等）。

### 方向
专项测试类（性能测试）

## Day 3 - 2026-06-10

### 题目
BUG 的严重等级如何划分？请以恐龙岛项目为例，用你最熟悉的玩法模块，为每个等级举一个具体的 BUG 例子。

### 答案

| 等级 | 说明 | 恐龙岛举例 |
|------|------|-----------|
| 致命（Blocker） | 游戏崩溃/核心流程阻断 | 点击"领地争夺"入口直接闪退，所有玩家无法进入该玩法 |
| 严重（Major） | 核心功能不可用 | 商城购买道具扣了钻石但道具未到账，影响付费体验 |
| 一般（Normal） | 功能异常但不阻塞 | 自动挂机在切换到后台 5 分钟后停止攻击，但 UI 仍显示"挂机中" |
| 轻微（Minor） | 不影响功能的瑕疵 | NPC 名字"迅猛龙"写成了"讯猛龙"，一看就出戏 |
| 建议（Suggestion） | 体验优化 | 背包满了弹出的提示"背包已满"只在屏幕上停 0.5 秒，根本来不及看清 |

核心理念：**致命 = 不能玩，严重 = 核心玩不了，一般 = 能用但不对，轻微 = 能用但不爽，建议 = 能用但可以更好。**

### 方向
BUG 管理类

## Day 4 - 2026-06-11

### 题目
恐龙岛领地争夺玩法中，多名玩家反馈"明明打赢了战斗，却没有获得领地所有权"。请分析可能出现这种情况的原因，并说明你会如何设计测试来覆盖这些场景。

### 答案

**可能原因分析：**

1. **并发竞争（最常见）**：两个队伍同时攻打同一块领地，A 队先打完但 B 队的战斗结算更晚写入，覆盖了 A 队的结果 → 并发写入导致数据覆盖。
2. **状态不一致**：客户端显示胜利，但服务端判定失败（比如战斗中某关键技能的伤害计算在服务端结果不同）→ 前后端判定逻辑不一致。
3. **条件未满足**：领地争夺有隐藏前置条件（如公会等级、参战人数下限），玩家赢了战斗但没满足占领条件 → 规则理解偏差。
4. **时序问题**：领地争夺有开放时间段，战斗打到最后一秒刚好过了截止时间，结算被丢弃 → 边界时间处理。
5. **数据同步延迟**：战斗结束后领地归属已更新，但客户端未及时刷新，玩家看到旧数据以为没拿到 → 显示层 vs 数据层。

**测试设计思路：**

- **并发场景**：模拟两队同时进攻同一领地，验证服务端是否有锁机制、最终结果是否一致
- **前后端一致性**：对比客户端战斗日志和服务端战斗日志，检查伤害/血量/胜负判定是否完全一致
- **规则验证**：逐一检查领地争夺的占领条件，确认每个条件在 UI 上有明确提示
- **时间边界**：在争夺截止前 1 秒发起战斗，截止前 0.1 秒结束战斗，验证结算是否正常
- **刷新验证**：战斗结束后强制刷新/重进游戏，确认领地归属显示正确

### 方向
逻辑场景题

## Day 5 - 2026-06-12

### 题目
游戏测试和传统软件测试有什么本质区别？以恐龙岛项目为例，说说什么情况下需要用"游戏测试思维"而非"纯软件测试思维"来设计用例。

### 答案

**核心区别：软件测试验证"对不对"，游戏测试还要验证"好不好玩"。**

具体差异：

| 维度 | 软件测试 | 游戏测试 |
|------|---------|---------|
| 目标 | 功能正确、无 BUG | 功能正确 + 体验流畅 + 趣味性 |
| 标准 | 客观（通过/不通过） | 主观 + 客观，主观占比大 |
| 性能关注 | 响应时间、并发量 | 帧率、卡顿、发热、耗电 |
| 兼容性 | 浏览器/系统版本 | 不同机型 + GPU + 分辨率 + 操作方式 |
| UI 测试 | 布局正确、交互正常 | 还要看美术表现、动效节奏、操作手感 |
| 用户行为 | 按预期路径操作 | 玩家会做各种"不按套路出牌"的事 |

**恐龙岛实例——什么时候用"游戏测试思维"：**

- **软件测试思维够用**：商城购买道具 → 验证扣钻石正确、道具到账、异常处理。和电商测支付没本质区别。
- **必须用游戏测试思维**：领地争夺战斗 → 不仅要验证胜负结算正确，还要关注：
  - 20人同屏战斗的帧率是否稳定（软件测试不测帧率）
  - 技能特效是否遮挡关键 UI（美术 + 交互）
  - 击杀反馈的震动/音效/飘字节奏是否"爽"（体验层）
  - 低端机玩 30 分钟后是否烫手（游戏独有维度）
  - 玩家连续打 10 场是否无聊（留存/疲劳度）
- **混合场景**：恐龙存储系统 → 数据存储/读取是软件逻辑，但"放生恐龙时那个动画快慢、提示是否清晰、误操作有没有二次确认"全是游戏体验。

一句话总结：软件测试保证"能用"，游戏测试还得保证"玩家愿意一直用"。

### 方向
基础概念类

## Day 28 - 2026-07-21

### 题目
恐龙岛的"恐龙乱斗排行榜"上线后，玩家反馈"明明赢了5场但排行榜没显示我的排名"。请分析排行榜系统可能出的问题，并设计完整的排行榜专项测试方案。

### 答案

排行榜是游戏中最容易出现"数据不一致"的模块，核心风险在**数据源→计算→展示**三层的断链。

**一、玩家看不到排名的可能原因（5类）：**

1. **数据上报失败**：客户端战斗结果未成功上报服务端（弱网/接口超时/客户端本地存储未提交）
2. **计算延迟/定时刷新**：排行榜不是实时更新的，而是定时（如每5分钟）刷新快照，玩家赢了但快照还没更新
3. **门槛过滤**：排行榜有最低场次/最低积分门槛，赢了5场但积分不够或场次不达标，被过滤掉了
4. **分区/分服问题**：玩家在A服，看的排行榜是B服的，跨服数据未合并
5. **缓存展示层**：客户端缓存了旧排行榜数据，未及时拉取最新数据

**二、排行榜专项测试方案（6大维度）：**

| 维度 | 测试要点 | 恐龙岛举例 |
|------|---------|-----------|
| **数据准确性** | 排行榜分数 vs 实际战绩是否一致 | 打了10场赢了8场，排行榜应显示8胜2负 |
| **排序正确性** | 同分排序规则、分数变化后排名实时/延迟更新 | 两个玩家都是100分，谁排前面？按胜率？按时间？ |
| **并发安全** | 同一玩家多次上报、多玩家同时结算 | 用JMeter模拟100人同时结算，排行数据不乱 |
| **刷新机制** | 实时刷新 vs 定时快照，刷新间隔是否合理 | 5分钟刷新一次，玩家赢了后等5分钟才更新，体验是否可接受 |
| **跨服/分区** | 合服后排行合并、不同服务器排行是否独立 | 恐龙岛3个服合并，Top100是否正确合并无重复 |
| **展示与边界** | 空榜、自己不在榜、榜尾、翻页、赛季切换 | 新赛季开始排行清空，旧赛季数据是否可查看 |

**三、关键边界场景：**
- 赛季切换前最后一秒赢了一场 → 积分计入旧赛季还是新赛季？
- 排行榜前10名中有人被封号 → 是否移除？替补玩家排名是否正确上移？
- 玩家改了名字 → 排行榜上名字是旧名还是新名？缓存多久更新？
- 合服时两个服的第一名积分相同 → 合服后谁是第一？

### 方向
排行榜系统测试类
