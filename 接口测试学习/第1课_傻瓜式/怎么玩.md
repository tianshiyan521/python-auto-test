## 二、这个练习台在演什么

你平时测游戏，点一个「领取」按钮，客户端偷偷发了一包数据给服务器，服务器回了一包数据。

**接口测试 = 不点按钮，直接跟服务器对话，看它回得对不对。**

练习台就是把这件事拆开给你看：

- **左边**：你发出去的请求（网址 + 参数）
- **右边**：服务器回来的响应（HTTP 状态 + 那段 JSON）

你每点一次「发送」，黑窗口里也会打印一行，那是"服务器视角"看到的东西。

## 三、7 个任务（页面底部有清单，做完会变绿）

| # | 做什么 | 你会看到 |
|---|--------|---------|
| 1 | 点「登录」 | 返回一个 token，相当于通行证 |
| 2 | 点「查角色信息」 | 当前等级 5、金币 1000 |
| 3 | 领「新手礼包」 | 成功，金币变成 1100 |
| 4 | **再领一次**新手礼包 | 报错 `50003 已经领过了` |
| 5 | 领「王者礼包」 | 报错 `50002 等级不足`（要 10 级） |
| 6 | 用 GM 工具把等级改成 **20**，再领王者礼包 | 这次成功了，金币 +1000 |
| 7 | 把顶部 token 框改成 `wrong`，随便发个请求 | 报错 `10002 token 无效` |

---

## 四、做完这 7 件事，你其实已经学会了 4 个核心概念

1. **接口就是**：一个网址 + 几个参数 → 返回一段 JSON。
2. **HTTP 200 ≠ 成功**。上面每次报错，HTTP 状态码都是 200，真正的成败写在响应体的 `code` 里。
   这就是为什么光看"请求有没有发通"没有意义，**必须断言 code 和 data**。
3. **同一个接口换参数，就是另一条用例**。任务 3 和任务 5 打的是同一个接口，只是 `rewardId` 不同。
   测试用例就是这么"设计"出来的：把参数取遍所有可能的值。
4. **token 是通行证**，任务 7 就是在测"鉴权有没有做对"。
